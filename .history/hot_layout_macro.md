# `#[hot_layout]` — detect struct layout changes

## Goal

Add a `hot_layout` proc macro that attaches to a struct. At boot, the host collects the
struct's content hash (`file:struct_name`) as the baseline. When a new `.so` is loaded,
compare hashes with the baseline; if a struct layout change is detected (fields added /
removed / modified, repr change, ...), the app `exit(0)`s so the wrapper respawns the
freshly built binary (the new binary carries the new struct layout).

## Mechanism

- Identical to the existing function comparison: `BTreeMap<String, u64>`, key =
  `file:struct_name`, value = **u64** hash of the whole struct definition (computed
  deterministically at compile time in the proc macro with FNV-1a 64 over
  `quote!(#item).to_string()`).
- Collected via `inventory`, like `HotFn`: the `crate::hot::HotLayout` struct is
  `inventory::collect!`-ed inside the `hot` module generated by `#[hot_main]`; the `.so`
  exports `hrl_get_layouts() -> Vec<hotfnl::HotLayout>`.
- Mismatch / extra / missing keys → `PatchErr::ToManyChange` (reused, NO new variant) →
  `run_watch_lib` already calls `std::process::exit(0)`.

## Notes

- `HotLayout` uses `u64` for the hash (final decision).
- No new `PatchErr::LayoutChanged` variant — `ToManyChange` is reused.
- Hash is computed over the struct definition at macro expansion (inventory requires a
  const literal); filename lives in the map key.
- The hash input is `fnv1a_64(format!("{}::{}", attr_str, core_str))`, where `attr_str`
  is all struct attributes converted to a string (prefix) and `core_str` is the struct
  definition with attributes stripped (to avoid hashing them twice).
